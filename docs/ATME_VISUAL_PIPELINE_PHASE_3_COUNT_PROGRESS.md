- Optional legacy-omitted `CountPolicy` requires one text target, canonical finite
  decimal strings, explicit unit/placement/separator/grouping, precision, named
  rounding, quantization level count and exact formatted endpoints. New writes
  require a complete policy and semantic text binding. Layout validates supported
  single-line text and an explicitly declared initial start; resolved chronology
  determines the actual first action rather than guessing from plan array order.
- State remains visible→visible. Integer-millisecond Fraction clock sampling uses
  the existing continuous easing equations, avoiding late one-third boundaries.
  `step_count` is quantization levels, not guaranteed displayed frames; typed Count
  cannot use step easing. Decimal formatting uses an explicit local context and
  never an operating-system locale. Every declared format is measured against
  pinned style/fonts and authored text bounds through immutable-key caching.
- A frozen Count-specific FrameObject subclass carries sampled text and exact
  rational numeric provenance. Non-Count FrameObject shape is unchanged. Repeated
  Counts require captured displayed-text equality and exact numeric equality;
  numerically equal spellings such as10 and10.0 are allowed. Completion versions
  only the text object once. SVG consumes actual sampled text with normal escaping.
- Existing overlap, Group, annotation, connection, Isolate and evidence consumers
  retain their guards. Count readiness checks sampled visible/full-reveal/positive
  opacity ancestry. Two generated distributable schemas add CountPolicy; legacy
  examples and other schemas remain unchanged. No internal semantic inference,
