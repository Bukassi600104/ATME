# ATME production audit and completion plan

ATME can export a movie from a saved executable timeline. The main remaining build is the storyboard compiler. A connected producer should be able to describe a diagram, name the spoken cue, supply evidence and request a return to the diagram. ATME should place and time those instructions locally, explain any instruction it cannot execute, and deliver the reviewed movie. Today a producer still supplies the rich layout and the finished action timeline.

## Corrections implemented in this source checkpoint

| Correction | What was checked |
| --- | --- |
| Public v2 preview now draws the frame displayed at the requested time. Camera and paper-background previews use the same frame clock as export. | Isolated copies of both packaged QA projects were scrubbed across frame boundaries. Six comparisons against frames 6, 7 and 8 of the retained MP4s had a worst channel mean absolute difference of 2.006 on a 0–255 scale. The preview held within each displayed frame and changed across the boundary. Millisecond inspection for source animation is still available. |
| New v2 submissions identify the action when move, scale or rotate carries opacity, or fade carries a spatial destination. | Project writes and storyboard proposals reject the incompatible channels. Supported transforms and explicit nulls remain usable. Historic spatial actions retain their sampled appearance. The renderer already rejected a fade with a destination. |
| Revision requests use the edited production duration. Legacy visual proposals can be previewed using the authored board duration while a recording is still in the media bin. | A shorter supporting import leaves the full edited range selectable. Trimming the edit rejects a selection past the new end. The legacy proposal check previews an image before acceptance and preserves the project revision until the proposal is accepted. |
| The connected client can now compile just the spoken triggers of a stored v2 storyboard. | A real MCP client resolved the second occurrence, applied an offset and obtained the same result on a repeated read. The operation reuses a completed timing measurement across storyboard changes, rejects a stale edit and reports beat, action and instruction IDs on failures. On a copy of a previously measured spoken QA recording, “the” occurrence two resolved to 3.120 seconds, “each request” resolved to 0.720 seconds and “queue” was flagged at confidence 0.659 against the default 0.75. |

The speech result includes word indices, timing and plan identifiers, and lists non-speech actions separately. It counts an exact phrase within a narration scene, with occurrences numbered across scenes in recording order. Incomplete word alignment currently requires review because the alignment store can omit unmatched words. The result covers spoken anchors. Building placements, action durations, other trigger types, board state and the finished timeline remains Phase 2 work. The previously packaged 0.1.3 installer predates these corrections. ## Next implementation

Use the queue film as the first compiler case. Board A shows incoming requests, board B shows an attributed observation, then board A returns with the changed relationship highlighted on the second spoken cue. Build the smallest set of semantic instructions that can produce that complete film. Store its source revision, measured words, assets, generated artifacts and encoded comparison so a failed step can be reproduced in isolation.

Create an original, rights-cleared reference production for editorial acceptance and a clean Windows build from declared dependencies. Preserve the existing engine, user projects, renderer, artwork and regression fixtures. Carry forward a completed case until an input, dependency or implementation it covers changes.
